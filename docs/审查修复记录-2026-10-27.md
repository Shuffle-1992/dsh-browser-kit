## 已修项要点

### F02 镜像 HTML 进宿主（P1，XSS 类）
- **根因**：`host.innerHTML = snap.html` 把 guest 渲染的面板 HTML 直接插进宿主**活动 DOM** ✗（跨文档信任提升）。
- **修法**：`DOMParser` 惰性解析（不执行脚本 / 不加载资源）→ `src/mirror-sanitize.mjs` 允许列表过滤 →
  `createElement` + `setAttribute` + `textContent` **重建** ✓ ⇒ guest 字符串**永不进 innerHTML** ✓；面板标记结构不变（零视觉回归）。
- **边界**：本机测试是**描述符级**反例 + 接线钉子；**未在真实 DSH CSP 下跑恶意载荷** ✗（报告 §8 未完成项第 3 条）。

### F04 凭据按 origin 匹配（P1）
- 旧：比较 `URL(x).host` ⇒ `https://a` 的凭据会匹配 `http://a` ✗（协议降级 + 忽略端口）。
- 新：`src/credential-origin.mjs` —— 页面默认必须 **https** ✓、按**标准化 origin** 逐字相等 ✓、条目协议不安全不参与 ✓；
  并在**填充执行时**用页面自己的 `location.origin` 复核 ✓（防"选中后导航"竞态）。

### F05 密码不进 Agent 上下文（P1，读取端）
- 旧：`browser_element_info` / `browser_snapshot` 回传**所有** `value` ⇒ 自动填充的密码被原样读回 ✗。

## 回归修复：F02 净化过度收紧导致批注面板渲染故障（2026-10-27 实机反馈）

**现象（用户截图）**：右下角批注面板只剩「蓝色编号徽标 + 一个空方块」✗。

**根因**：我第一版 F02 净化把安全边界划得**过宽** ✗ ——
① 整表禁用了 `svg` ✗，而面板图标**就是内联 SVG**（折叠态只有徽标 + 两个图标按钮）⇒ 图标全被剥掉、只剩空方块 ✗；
② `style` 用了**属性白名单** ✗，面板样式里未被列举的属性被静默丢弃（实测缺 `transform-origin` ✓，将来还会漏 ✗）；
③ 属性名被统一小写 ✗ ⇒ SVG 大小写敏感属性（`viewBox`）失效 ✗；
④ `data-on` / `data-state` 不在 data 前缀白名单里 ✗ ⇒ 状态属性被丢 ✗。

**修法（安全边界不变 ✓）**：
- 放行**纯几何 SVG 子集**（svg/g/path/circle/rect/line/polyline/polygon/title ✓），
  危险成员（script、foreignObject、use、image、animate 系列、set、feImage）**仍然禁止** ✗；svg 上的 `on*`/外链属性照旧剥离 ✗；
- `style` 改为**只拦危险模式**（url()/expression()/@import/javascript:/-moz-binding/behavior: ✓ ⇒ 整条丢弃），
  其余属性名只做合法性校验（含 `--custom` ✓）—— CSS 本身不能执行 JS，能外带资源的只有 url() 一类（已拦 ✓）；
- 属性名**保留原始大小写**（校验用小写 ✓）⇒ `viewBox` 等 SVG 属性正确 ✓；
- data 白名单增加精确项 `data-on` / `data-state` ✓（惰性属性 ✓）。

**新增钉子（防再犯 ✓）**：
- `F02 实机回归：面板图标（安全 SVG 子集）必须保留，危险成员必须剥掉` ✓；
- `F02 实机回归：折叠态面板整体必须原样存活（图标 / 样式 / data 属性）` ✓
  —— 这条把「面板该长什么样」钉成契约，任何"净化过头"的改动都会立刻变红 ✓。

**教训**：安全净化要**按"能不能执行/外链"划边界** ✓，不要按"我见过哪些属性"划边界 ✗ ——
后者会随 UI 改动不断误伤，而且故障现象（空白方块）与安全无关，很容易被误判成布局 bug ✗。

## 第三轮（正解）：宿主**结构化渲染**面板，彻底不搬 guest HTML ✓

**为什么不再净化**：上一轮给镜像加"允许列表净化"后，面板仍然渲染成空白方块 ✗（真机第二轮 ✓）——
根因是**思路本身**：只要还搬 HTML，就要不断猜"哪些标签/属性/样式是面板需要的" ✗，
猜漏一个 SVG 或一条样式就是可见故障 ✗，而且故障现象（空白方块）与安全无关，极易误判 ✗。

**改法（也是审查报告 §7 第 3 条的建议 ✓）**：
- guest 侧新增 **`mirrorData()`** ✓：只回**纯文本结构化数据** `{rev, count, list:[{n, note, tag, label}]}` ✓；
- 宿主侧新增正典 `src/annot-mirror-view.mjs`（视图模型：标题/条数/条目/截断/上限 ✓）+ client 内嵌副本（A2 parity ✓）；
- 宿主用 `createElement` + `textContent` + **自己的主题令牌**（`T.bg/T.border/T.shadow/T.accent` ✓）渲染面板 ✓，
  结构保持 `children[0]=头部 / children[1]=列表体 / children[2]=底部` ✓（既有绑定与列表显隐逻辑零改动 ✓）；
- **删除** `src/mirror-sanitize.mjs` 与它的测试 ✗（面板不再有 HTML ⇒ 净化成为死代码 ✓，按项目规矩不留 ✓）。

**收益**：
- F02 的问题从"净化得够不够严"变成"**根本没有跨文档 HTML**" ✓ ⇒ 信任边界与渲染稳定性一起解决 ✓；
- 面板不再依赖 guest 的 CSS/图标/属性 ⇒ 页面改样式也不会把宿主面板带坏 ✓；
- 少一个模块、少一套允许列表维护 ✓（复杂度下降 ✓）。

**新增钉子** `test/annot-mirror-panel.test.mjs`（8 例）：视图模型（空态/条目/截断/上限/脏数据 ✓）、
重绘判定（rev ✓）、两端 parity ✓、**架构钉子**（宿主不得再调 `mirrorSnapshot`、`innerHTML` 只允许写自家图标常量 ✓、
面板结构顺序 ✓、`mirrorData` 不得回 HTML ✓）。

> ⚠️ 仍待实机确认：本轮改动是**客户端侧** ⇒ 需重启 DSH 后看面板实际渲染 ✓。

### F03 自持窗口无会话所有权（P1）
- **现状**：`agentView` 是**全局单例** ✗，`target=agent` 直接返回它；`scopeCheck` 只要有自持窗口就放行；
  `guest-eval` 未列入 `PAGE_ACTIONS`；多处 `inputTargetOf(c) || pickGuestEl()` 会**回退**到别的目标 ✗。

  且验收要求 **A/B 双会话实机**（读/写/导航/关闭/eval 全覆盖）✓ —— 本机只有单会话交互，无法给真证据 ✗。
- **建议顺序**：① 删掉"目标不存在就找任意窗口"的回退 ✓（小、可单测 ✓）；② 自持窗口记录 `sessionId` 并在所有路径校验 ✓
